# 面談申請画面：希望日時の選び方を作り直す

作成日: 2026-08-03

## 背景

インターン生の「面談を申請」画面は、いま次のようになっている。

- 空き枠を1マスずつクリックして選ぶ（最大3つ / `index.html:1741` `1788`）
- クリックした順に第1〜第3希望の番号が付く
- 選んだ日時は「面談方法」の上に一覧表示される（`index.html:1752`）
- 面談方法（Google Meet / Zoom）を必ず選ぶ（`index.html:1772`）

実際の運用では面談方法は常に決まっており、選ばせる意味がない。
また、候補を3つ出すのに3回クリックが必要で、
「この日の午後はどこでもいい」といった出し方ができない。

## 決定事項

利用者との確認により、次のとおり決めた。

| 論点 | 決定 |
|---|---|
| 面談方法 | アプリ全体から削除する |
| 希望の上限 | なし（何件でも選べる） |
| 選びすぎの警告 | 出さない |
| 希望順の付き方 | なぞった順に自動採番。一覧でドラッグして並べ替えられる |
| 並べ替えのつかみ方 | 行のどこでも持てる。↑↓ボタンは置かない |
| スマホでの挙動 | 長押しを待たず、指を置いてすぐ並べ替えが始まる |
| 「必須」の意味 | 1件以上選ぶこと。順位が飛ばないことを保証する |

## 変更内容

### 1. 面談方法をアプリ全体から削除

`MTYPE` 定数（`index.html:511`）と、その参照7か所を消す。

| 場所 | 変更後 |
|---|---|
| 申請画面のラジオ（`index.html:1772`） | 削除 |
| 面談状況のタグ（`1822`） | 削除 |
| 面談状況の確定案内（`1827`） | 「面談のリンクはメールで届きます」 |
| 面談一覧の副題（`1875`） | 「申請 3日前」だけにする |
| 面談詳細の面談方法の行（`1917`） | 行を消すと `<dl class="kv">` が空になるため `<dl>` ごと削除 |
| 面談詳細のリンク送付ボタン（`1904`） | 「面談リンクを送る」／件名「面談リンクの送付」 |
| 確定メール本文（`1938`） | 「方法：…」の行を削除 |
| ホームのタイル（`2221`） | 日時だけにする |
| カレンダーの一覧（`2277`） | 時刻だけにする |
| Googleカレンダーの説明文（`server.js:875`） | 「OPS日調アプリで確定した面談です。」だけにする |

`/api/interviews` は `meeting_type` を受け取らず、保存もしない（`server.js:2080` `2094`）。

既存の面談データに入っている `meeting_type` は消さない。
参照されなくなるだけなので、DBの移行は不要で、過去の面談も従来どおり開ける。

### 2. 希望日時を配列で持つ

上限をなくすため、`choice1` `choice2` `choice3` の3項目を `choices` 配列に置き換える。
`interviews` テーブルの `data` はJSON列なので（`server.js:194`）、テーブル定義の変更は要らない。

**読み出し**は互換関数を1つ設けて、そこだけを通す。

```js
function ivChoices(iv){
  if(Array.isArray(iv.choices)&&iv.choices.length)return iv.choices;
  return [iv.choice1,iv.choice2,iv.choice3].filter(Boolean);
}
```

これで既存の面談（`choices` を持たない）もそのまま表示できる。
呼び出し先は面談状況（`index.html:1833`）と面談詳細（`1896`）の2か所。

**保存**時は `choices` を送る。サーバーは受け取った内容を次の順で1本の配列にまとめる。

1. `choices` が中身のある配列ならそれを使う
2. なければ `choice1` `choice2` `choice3` の空でないものを並べる（旧形式の受け口）
3. それでも空なら従来どおり 400（「希望する枠を選んでください」）

まとめた配列を `choices` として保存しつつ、先頭3件を
`choice1` `choice2` `choice3` にも入れる。
これは、万一この変更を巻き戻したときに申請が読めなくなるのを防ぐため。

面談詳細（`index.html:1888`）の候補リストは3件固定をやめ、
`ivChoices(iv)` の件数ぶん「第N希望」の行と「これで確定」ボタンを並べる。

### 3. カレンダーをドラッグで複数選択

スタッフの「面談できない時間を登録」と同じ方式にする
（`avPointerDown` / `avDragMove` / `avDragEnd` / `index.html:2647`）。
申請画面用に `applyPointerDown` / `applyDragMove` / `applyDragEnd` を新設する。

- 空き枠（○）のセルに `data-iso` と `onpointerdown` を付ける
- 押し始めたセルが未選択なら**追加モード**、選択済みなら**解除モード**。
  ドラッグ中はそのモードのまま、なぞったセルに同じ操作を適用する
  （不可時間の登録と同じ考え方で、往復しても行ったり来たりしない）
- 追加は配列の末尾に積むので、**なぞった順がそのまま希望順**になる
- ドラッグ中はセルの表示だけを直接書き換え、指を離してから `render()` する。
  解除モードでは後続の番号が一時的にずれるが、離した時点で詰め直される
- 保存はしない。従来どおり「申請する」を押したときだけ送信する

1マスだけタップした場合も同じ経路を通るので、いまの操作感は失われない。

上限の撤廃にあわせて次も直す。

- `toggleSlot` の「3つまで」の判定を削除（`index.html:1788`）
- ラベル「日時を選ぶ（0/3）」→「日時を選ぶ（0件選択中）」（`1768`）
- 説明文「空いている30分枠を最大3つまで選んでください（第1〜第3希望）」→
  「空いている枠をなぞって選び、下の一覧で希望順に並べ替えてください」（`1759`）

### 4. 選んだ日時をドラッグで並べ替える

「その他」のすぐ上（面談方法を消した結果ここに来る）の一覧を並べ替え可能にする。

```
選んだ希望日時（3件）　上から第1希望です
  ①  8月10日(月) 14:00                    ×
  ②  8月10日(月) 14:30                    ×
  ③  8月12日(水) 10:00                    ×
```

- 行のどこを持ってもドラッグできる。`selDragStart` を `pointerdown` に付ける
- 長押しを待たずに始める。そのため行に `touch-action:none` を当て、
  ブラウザ既定のスクロールに指を取られないようにする。
  一覧の外側に触れればページはスクロールできる
- `pointermove` では `document.elementFromPoint` で重なっている行を探し、
  掴んでいる行との位置を入れ替える。配列を直接 `splice` で動かす
- 並べ替え中は一覧だけを描き直す軽量な関数を使う。
  画面全体の `render()` を毎フレーム呼ぶとカレンダーまで描き直すことになり重い
- 掴んでいる行には `.dragging` を付け、浮いて見えるよう影と半透明にする
- 「×」は `pointerdown` を親に伝えない。ドラッグの開始と削除が競合しないようにする

### 5. 希望順の必須化

配列の並びがそのまま希望順なので、追加・解除・並べ替えのいずれでも
番号は常に1から連番になり、飛ぶことがない。
`submitApply` は従来どおり、1件も選ばれていなければエラーにする。

## 変更後の挙動

- インターン生は面談方法を選ばなくなる。確定後のリンクは従来どおりメールで届く
- 候補は何件でも出せる。スタッフの面談詳細には出された件数ぶん候補が並ぶ
- 過去の面談（`choices` なし・`meeting_type` あり）も、そのまま開ける

## 対象外

- 既存データの移行（`meeting_type` の削除、`choices` への一括変換）
- スタッフ側での面談方法の選択
- 候補の件数に応じた警告や上限

## テスト（`tools/e2e.mjs`）

1. `choices` 配列で `/api/interviews` に申請でき、保存された面談から
   同じ順序の `choices` が返る
2. `choice1` だけを送る旧形式でも申請でき、`choices` に変換されて返る（互換の確認）
3. `choices` が空、または `choice1` もない場合は 400 になる
4. `meeting_type` を送っても無視され、保存内容に含まれない

ドラッグ操作そのものはブラウザ上の挙動のため、e2eの対象外とし、手動で確認する。
