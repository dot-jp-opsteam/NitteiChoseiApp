# インターン生のアカウント廃止と、支部リンクからの面談申請

状態: **実装完了・未デプロイ**（2026-08-04）

## 1. 目的

インターン生に手間をかけさせない。会員登録もログインも無しで、**本名を入れるだけ**で
面談を申し込めるようにする。

## 2. 決めたこと（すべてユーザー承認済み）

| 論点 | 決定 |
|---|---|
| 申請後にインターン生が状況を見に来るか | **来ない**。一度きりの申請で完結する |
| 確定日時の連絡方法 | **アプリ外**（LINE等）でスタッフが直接連絡する |
| イベント出欠 | スタッフしか使っていないため、影響なし |
| 悪用対策 | **推測できないURL**のみ。合言葉の入力は求めない |
| 既存のインターン生 | **ログインは止め、行と過去の面談は残す** |
| インターン生あての依頼 | 使っていないため**廃止**（宛先の選択肢から外す） |

## 3. インターン生の記録の持ち方

**採用した案**：`interviews` に `intern_name` を持たせ、`intern_id` は空文字にする。
ユーザー行は作らない。

- `interviews.intern_id` は `NOT NULL` なので、`''`（空文字）を入れる。
  **スキーマ変更が不要**になり、移行作業が発生しない
- 名前は `data` のJSONに入る（`saveInterview` が列以外を自動でJSONに寄せるため）
- 過去の面談（`intern_id` にユーザーIDが入っているもの）とそのまま共存する

**不採用にした案**：
- 申請ごとにゲスト用のユーザー行を作る → `users.email` が NOT NULL かつ重複不可のため
  スキーマ変更が必要。ユーザー管理画面が実体のない行で埋まる
- 名前で名寄せして履歴をまとめる → **同姓同名で他人の履歴が見える**。個人情報の事故になる

## 4. 作りと流れ

```
支部リンク  https://.../i/<合言葉>
  ↓  GET /api/apply/:token        支部名と、その支部のスタッフ一覧
  ↓  GET /api/apply/:token/slots  選んだスタッフの空き枠
  ↓  POST /api/apply/:token       本名・スタッフ・希望枠・伝えたいこと
面談レコード（intern_id='' / intern_name='山田 太郎'）＋ 支部への通知
```

### 支部リンク

- `branch_invites` テーブル（`branch_id` / `token` / `created_at` / `created_by`）
- **`store` の `branches` には入れない。** `/api/branches` はログイン不要で誰でも読めるため、
  そこに入れると合言葉が漏れる
- 合言葉は 24バイト乱数（48文字）。最初に必要になった時点で作る
- 漏れたときは支部管理者が作り直せる。作り直すと古いリンクは即座に無効になる

### 空き枠の計算

`server/slots.js` に移した（`generateSlots` / `isSelectableSlot`）。

画面ごとに規則がずれるのを防ぐため、**枠の判断はサーバーだけが持つ**。
申請ページは受け取った枠を並べるだけ。

送られてきた希望枠は保存前に `isSelectableSlot` で必ず検証する。
画面を細工されても、埋まった枠や受付時間外を掴まされない。

### 申請ページ

`apply.html`（新規）。`index.html` には**組み込まない**。

`index.html` は5000行近くあり、ログインを前提とした作りなので、そこにログインしていない
人向けの経路を混ぜると事故が起きやすい。分けておけば、**アプリ本体のログイン処理に
一切触れずに済む**。

`/i/<合言葉>` は `apply.html` を返す。合言葉の正しさはここでは見ない。
ここで弾くと、URLを叩くだけで合言葉の当たり外れが分かってしまうため。

## 5. 塞いだ入口

インターン生が入れる経路は複数あるため、**`requireAuth` の1か所で止める**。
塞ぎ忘れを防ぐのが狙い。

| 入口 | 対応 |
|---|---|
| `requireAuth` | `role === 'intern'` を401で拒否（残っているセッション・Googleログインもここで止まる） |
| `POST /api/auth/login` | インターン生は403。案内文を返す |
| `POST /api/auth/register-intern` | 410 |
| `POST /api/interviews` | 410（到達不能になったため） |

## 6. 画面側の変更

- **リンク作成**：個人ごと → **支部ごとの共通リンク**。支部管理者には「作り直す」ボタン
- **面談一覧・詳細**：`ivInternName()` で表示。アカウントがあれば従来どおりニックネーム、
  無ければ入力された本名
- **見える範囲**：`intern_id` が空だと所属で判定できないため、**支部の一致**でも見せる
  （サーバーの `listInterviewsFor` と画面の両方）
- **メール送信**：アカウントの無い申請では宛先が無いので、ボタンを隠して案内を出す。
  確定・不成立のあとにメール作成画面へ進む動きも止める
- **依頼の宛先**：インターン生あての3つ（全インターン生／インターン生を選ぶ／インターン先で選ぶ）を外す

## 7. テスト

`node tools/e2e.mjs` は **164件**（97件から増加）。

テスト利用者を組み替えた。インターン生が担っていた「同じ支部の他人」の役は、
同支部のスタッフ（`staff3` / `staff4`）が引き継いでいる。`oldIntern` は、
**残っているインターン生のセッションが弾かれること**を確かめるためだけに使う。

主な検証：
- 支部リンクの取得・支部ごとに別のURL・作り直しで古いURLが無効になること
- でたらめな合言葉では支部の情報が一切出ないこと
- 他支部のスタッフは選べない・枠も見られない・申請もできないこと
- 埋まった枠・過ぎた日時は申請できないこと
- 100人が同時に申請して全員成功すること
- 廃止した入口が410／401を返すこと

## 8. 積み残し

- **既存のインターン生アカウントは残っている。** ログインできないだけで、行は消していない。
  整理するかどうかは別途判断する
- 同姓同名は区別されない。スタッフは名前と申請日時で判断する
- 申請ページには回数制限を入れていない。合言葉が漏れた場合の連投は、
  リンクの作り直しで対処する

## 9. デプロイ時の注意

- `branch_invites` テーブルは起動時に自動で作られる。手作業は不要
- 既存データの移行は**発生しない**（スキーマを変えていないため）
- インターン生がログインできなくなるので、**切り替え前に支部リンクを配っておく**こと
