# 申請画面の不具合修正と「終日OK」

状態: **本番反映済み**（2026-08-05／`51e92a0`）

## 1. 直した不具合

### 1.1 表示される日時が9時間ずれていた（重大）

**本番（Render）はUTCで動いている。** 空き枠は `server/slots.js` が
`setHours()` で組み立てているため、「9:00の枠」が**UTCの9:00＝日本時間の18:00**
として作られていた。

その結果、

- 申請ページの表には「10:00」と出るのに、実体は `…T10:00:00.000Z`＝**日本時間19:00**
- 選ぶと、下の「選んだ希望日時」には日本時間で解釈した19:00が出る
  → **選んだ時刻と違う時刻が出る**。ずれで日付をまたぐ場合は日付も変わる

**直し方**：`server/server.js` の先頭で `process.env.TZ = 'Asia/Tokyo'` を指定した。
Date を1度でも使う前に決める必要があるので、`require` より先に置いてある。

サーバー側で時計を見て日付を組み立てているのは `server/slots.js` だけなので、
影響範囲はここに限られる（確認済み）。

**⚠️ 既に届いている申請は、時刻がずれたまま保存されている。** 8/5の
この修正より前に本番で申し込まれたものがあれば、9時間先の時刻が入っている。
件数を数えて、あれば直す必要がある（§5）。

### 1.2 続けて選んだ時間がひとつにまとまらなかった

指を**速く動かすと途中のマスが飛ばされていた**。
「指が実際に通ったマス」だけを選ぶ作りだったため、`pointermove` が届かなかった
行が抜け、選んだ時間に穴が空いて希望が2つにも3つにも割れていた。

実際に、6マスぶんを一気になぞる操作を再現したところ**1マスしか選ばれなかった**。

**直し方**：押し始めたマスから今いるマスまでの**範囲ぜんぶ**を選ぶ方式に変えた。
毎回「なぞる前の状態」から組み立て直すので、指を戻せば選択も戻る。
行の判定には指の高さだけを使う（列は押し始めた日に固定されているため）。
`elementFromPoint` に頼らなくなったので、マスの境目でも取りこぼさない。

## 2. 「終日OK」

日付の見出しの下にボタンを置き、その日の空いている枠をまとめて選べるようにした。
もう一度押すと解除。空きが1つも無い日は押せない（「—」）。

**印は選択そのものから導く。** その日の空き枠がすべて選ばれていれば終日OK、
1つでも外れれば解除。別に印を持って食い違うより確実で、
手で全部選んだ場合も自然に終日OKとして扱われる。

### 途中に埋まった時間があるとき

**その日ぜんぶで1件の希望にまとめる。**

```
第1希望  8/7(金) [終日OK]
         10:00〜12:00 ＆ 13:30〜18:00
```

「この日はいつでもいい」という申し出を2つにも3つにも割ってスタッフに見せると
かえって分かりにくいため。**終日OK以外**（手で飛び地に選んだ場合）は、
今までどおり続き具合で分ける（2026-08-05にユーザーが選択）。

### スタッフ側にも伝える

終日OKにした日を `all_day`（`['2026-08-07']`）として申請と一緒に送り、
`interviews` の `data` に持たせる。スタッフの面談詳細でも同じまとめ方になり、
「終日OK」の印が付く。

`all_day` を持たない申請（この仕組みより前のもの）は、今までどおり続き具合だけで分ける。

## 3. 受付時間まわりの変更（ユーザー指示）

| 項目 | 前 | 後 |
|---|---|---|
| 表の縦軸 | その週の受付時間に合わせて伸び縮み | **いつも9:00〜23:00（28行）** |
| 受付時間の既定値 | 平日9〜19時／土10〜16時／日は休み | **曜日を問わず9〜23時** |
| 先の週 | 4週先まで | **2週先まで** |
| 1回に選べる枠 | 40枠 | **600枠** |

- 表の高さを固定したのは、週を移るたびに行がずれて同じ時刻を探しにくくなるため。
  受け付けていない時間は「×」として並ぶ
- 既定値を広げたのは、受付時間を設定していないスタッフでも実際に選んでもらうため。
  `index.html` の `DEFAULT_WEEKLY` も同じ値に揃えてある（**片方だけ直さないこと**）
- 枠の上限は「終日OKで1日28枠」を前提に、見られる範囲をすべて選んでも通る幅にした

## 4. テスト

`node tools/e2e.mjs` は **190件**（183件から増加）。足したのは、

- 表がいつも9:00始まり・22:30終わりの28行になること
- 先の週が2週で止まること
- 終日OKの日（`all_day`）が保存され、日付の形でないものは捨てられること
- **表の見出しの日付・時刻と、枠の実際の日時が一致すること**（9時間ずれの再発防止）

ブラウザでも、UTC環境のサーバーに対して次を確かめた。

- 「見出し10:00」＝「日本時間10:00」で一致

- 12:00〜13:30が不可の日で終日OKを押すと、
  「10:00〜12:00＆13:30〜18:00」の**1件**になること
- スタッフ側でも同じまとめ方・「終日OK」の印が出ること

## 6. 見た目の調整（2026-08-05・反映後）

ユーザーの指示で3点直した。

| 直したこと | 理由 |
|---|---|
| 並べ替え中に番号を振り直さない | 動かしている最中に数字がくるくる変わると、どこへ置こうとしているのか分からなくなる。指を離した時点で `refreshApplyLive()` がまとめて振り直す |
| 「終日OK」の枠線を外し、チェックの四角を付けた | 枠で囲むと表のマスに紛れて見出しに見え、押せると気づかれない恐れがあった。四角は文字（☑）だと端末によって出ないのでCSSで描いている |
| 表のマスも希望順で色を変えた | 第1＝赤・第2＝金茶・第3＝緑。一覧の「第1希望」の札と同じ色を使い、表を見ただけで順位が分かるようにした。第4以降はもとのエメラルドのまま |

色は `style.css` の `--rank1` / `--rank2` / `--rank3` をそのまま使っている。
申請ページはライト固定なので、暗い配色での見え方は考えなくてよい。

### この調整で踏んだ落とし穴：apply.html がビルド対象に入っていなかった

`apply.html` だけを直して push したところ、**10分待っても本番が変わらなかった**。

Renderの Build Filters（Included Paths）に `server/**` / `index.html` / `style.css` /
`privacy.html` / `terms.html` はあったが、**`apply.html` が抜けていた**。
`rootDir: server` のため、対象に入っていないファイルだけの push はビルドがスキップされる。

これまで気づかなかったのは、申請ページを作ってからの push が
毎回 `server/` か `index.html` も一緒に変えていたため。

対応：

1. `render.yaml` の控えに `apply.html` を追記した
2. 今回ぶんを届けるため `server/package.json` の version を上げて `server/` に触れた
   （実際に触れた直後にビルドが走った＝原因の裏付けになった）
3. **⚠️ ダッシュボードの Build Filters → Included Paths にも `apply.html` を足すこと。**
   `render.yaml` はBlueprint管理ではないので効かない。ここが済むまで、
   `apply.html` だけを直した push は本番に届かない
