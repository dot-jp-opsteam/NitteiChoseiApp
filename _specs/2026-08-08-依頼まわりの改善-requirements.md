# 依頼まわりの改善（要件）

このファイルは「何を作るか」だけを書く。作り方（どの関数を直すか、どんなHTMLにするか）は
実装する人がコードを読んで決める。

## 全体の決まりごと（すべての項目に共通）

- **npm の依存を増やさない。** Node の標準ライブラリだけで作る
- クラス名には接頭辞を付ける。`empty` `mark` `on` のような短い名前は
  このアプリの別の用途と衝突する（過去に2回、テストが全部通ったまま画面だけ壊れた）
- `style.css` に書いたルールは、`apply.html` / `attendance.html` の `<style>` に負けることがある。
  この2つは `<link href="/style.css">` の**後**に自前の `<style>` を持っている
- ダークモードで色が沈まないこと。スマホ幅（375px）で崩れないこと
- 変更のたびに `node tools/test-fmt.mjs` と `node tools/e2e.mjs` を通す
- `tools/e2e.mjs` は `index.html` / `style.css` の**文字列そのもの**を検査している項目がある。
  仕様を変えたらテスト側も新しい仕様に合わせて直す（消すのではなく、新仕様の確認に書き換える）
- **関数を消したら、呼び出し口が残っていないか名前で検索して確かめる**
- 既存の依頼データ（本番にすでにあるもの）が表示できなくなってはいけない。
  新しく足す項目は、無い場合でも壊れないようにする

## 項目4: iPhone標準カレンダーとの連携（購読URL方式）

自分の予定（面談・支部イベント・出欠が確定した予定）を、
iPhoneの「カレンダー」アプリやGoogleカレンダーから**購読**できるようにする。

### 仕組み

- 個人ごとに、推測できない長いランダムな文字列（購読キー）を1つ発行する
- `GET /api/calendar/<購読キー>.ics` で iCalendar 形式のテキストを返す。
  この経路はログイン不要（キーそのものが合鍵）。**キー以外の方法では中身を出さない**
- 設定画面に「カレンダーに登録」の欄を作り、購読URLをコピーできるようにする。
  あわせて「キーを作り直す」ボタンを置く（作り直すと古いURLは無効になる）
- 手順の説明を短く添える（iPhone: 設定 → カレンダー → アカウント → その他 →
  照会するカレンダーを追加 / Googleカレンダー: 他のカレンダー → URLで追加）

### iCalendar の中身

- `BEGIN:VCALENDAR` / `VERSION:2.0` / `PRODID` / `CALSCALE:GREGORIAN`
- 予定ごとに `VEVENT`。`UID`（アプリ内のIDから作る、ずっと変わらない値）、
  `DTSTAMP`、`DTSTART`、`DTEND`、`SUMMARY`、`DESCRIPTION`、`LOCATION`（あれば）
- 時刻はUTC（末尾 `Z`）で書く。終日の予定は `VALUE=DATE` で書く
- 行は75オクテットで折り返す（続きの行は先頭に空白1つ）。改行は CRLF
- `,` `;` `\` と改行は本文中でエスケープする
- 予定が消されたときに購読側からも消えるよう、**その人の予定を毎回すべて出し直す**
- `X-WR-CALNAME` にカレンダー名（例: OPS日程調整）を入れる
- 応答の `Content-Type` は `text/calendar; charset=utf-8`

### 入れる予定の範囲

- 確定した面談（自分が担当・自分が申請したもの）
- 自分が対象の支部イベント
- 過去は3か月前まで、先は1年先まで

### 気をつけること

- 購読キーは推測されない長さにする（32文字以上のランダム）
- 存在しないキーは 404 を返す。中身の有無で違いが分からないようにする
- 購読アプリは数時間おきに取りに来る。重い処理を毎回しない

## 項目5: 締切日（回答期限）

### 設定する側

- 出欠確認を作る画面と、依頼を出す画面の**両方**に「締切日」を置く
- **任意。** 設定しないまま送れる
- 入力は日付を1つ選ぶ形（`<input type="date">` のような、押すと日付選択が出るもの）。
  画面の場所を取らないこと。ミニカレンダーを常に開いた形にはしない
- 昨日以前は選べない

### 見せる側

- 受けた依頼の一覧と詳細に、締切日を出す（設定されているときだけ）
- 出欠の回答画面（ログインした人の画面と、公開の回答ページの両方）にも出す
- 締切を過ぎたものは「締切を過ぎています」と分かるようにする。
  **ただし回答自体は締切後もできる**（締め切って回答を止めるところまではやらない）

### ホーム画面のお知らせ

締切日が設定されていて、まだ回答（または完了）していない依頼について、
**締切の3日前になったら**そのスタッフのホーム画面にお知らせを出す。

- 出欠確認と通常の依頼の**両方**が対象
- 「〇〇の回答期限まであと2日です」のように、残り日数と件名が分かる形
- 押すとその依頼へ飛べる
- 締切当日も出す。締切を過ぎたら消す
- 対象が複数あるときはまとめて出す（1件ずつ積み上げない）
- 残り日数は「日付の差」で数える。時刻は見ない（今日が締切なら「今日まで」）

## 項目6: 依頼画面の作り直しと「完了」

### タブの構成

いまの「受けた依頼／送った依頼」の切り替えを、**「受けた依頼／完了済みの依頼」**に変える。

「送った依頼」は、画面の**右下に浮かぶ丸いボタン**に移す。
押すと同じ画面のまま送った依頼の一覧に切り替わり、丸いボタンは「戻る」に変わる。
もう一度押すと元の一覧に戻る。

- 丸いボタンはスクロールしても位置が変わらない
- 依頼を出せない人（インターン生）には丸いボタンを出さない
- 一覧の下端が丸いボタンに隠れないよう、下に余白を取る

### 「確認しました」→「完了」

依頼を受けた人の画面のボタンの文言を「確認しました」から**「完了」**に変える。

- 押すと、その依頼は「完了済みの依頼」タブへ移る
- **押し間違えたときのために、あとから取り消せる。**
  完了済みの依頼を開くと「完了を取り消す」ボタンがあり、
  押すと「受けた依頼」タブへ戻る
- 完了・取り消しは押した本人だけの状態。他の人の表示には影響しない

### 完了の対象

**通常の依頼だけ。** 出欠確認には「完了」ボタンを出さず、
回答済みでも「受けた依頼」タブに残す。

（理由: 出欠確認は回答することが完了なので、ボタンを二重に置くと迷う）
