# 候補日時UIの刷新

出欠確認をつくるときの「候補の日時」の入力を、日付入力欄の並びからミニカレンダー方式へ変える。
あわせて時刻の指定をホイール式にし、同じ日の別時間帯を足す手段を用意する。

対象は `index.html` の依頼フォーム（`reqOptionsHTML` まわり）。出欠を答える側の画面
（`attendance.html`、公開ページ）は変更しない。

## なぜ変えるか

いまは候補を1件ずつ「日付入力欄＋時刻入力欄」で足していく。候補が5件6件になると
入力欄がそのぶん縦に並び、どの日を選んだのかが一目で分からない。
面談申請の画面（`apply.html`）は週のグリッドをなぞって希望を出せるので、
出す側と答える側で操作感がそろっていない。

## 変えるもの

### 1. ミニカレンダー

「候補の日時」の見出しの直下に、1か月分のカレンダーを常に開いた状態で置く。
その下に、選んだ候補が今までどおり縦に並ぶ。

- 7列×5〜6行の月カレンダー。左右の矢印で月を送る
- 日付をなぞると、その範囲をまとめて候補に足す
- すでに選んである日からなぞると、その範囲をまとめて外す
- 今日は選べる。昨日以前は薄く表示して押せない

なぞる操作は `apply.html` の `applyPointerDown` / `applyDragMove` / `applyDragEnd` と
同じ組み立てにする。ただし向こうは「週×30分枠」の二次元グリッドで、こちらは日付だけの
一次元。共通化はせず、それぞれの画面で完結させる（`apply.html` は ES5 風の別世界で、
むりに寄せると両方が読みにくくなる）。

### 2. 「日程を設定しない」タブの削除

`REQFORM.noDate` と `setReqNoDate()` を消す。タブは「時間を設定する」だけになる。

サーバー側（`server/server.js` の `normalizeAttendOption`、`has_date === false` の分岐）は
**残す**。すでにこの形で作られた依頼が本番にあった場合、表示と回答ができなくなるため。
画面からは常に `has_date: true` を送る。

### 3. 同じ日をコピーするボタン

候補の行の、日付の左隣に置く。

- 押すと同じ日付の候補をもう1件足す
- 時刻は前の候補の終了時刻から始め、長さは維持する（`19:00〜21:00` → `21:00〜23:00`）
- 終了がその日に収まらないときは翌日の `00:00` から始める（`21:00〜23:00` → 翌日 `00:00〜02:00`）

時刻の上限は `23:59`。`24:00` は入力できない（サーバーの `validAttendTime` が `23:59` まで）。
そのため「終了が 24:00 を越える」ではなく「終了が **23:59 を越える**」を繰り上げの条件にする。
`22:00〜23:00` をコピーすると `23:00〜24:00` になってしまうので、これも翌日 `00:00〜01:00` へ送る。

繰り上げた先が翌月になる場合、カレンダーの表示月は変えない。候補の一覧には出るので、
月を送れば選択済みとして光る。
- 「時間を設定する」がONのときだけ表示する

OFFのときに隠すのは、見た目の都合ではなく意味がないため。時刻を持たない候補は
日付だけで区別されるので、同じ日をコピーしても中身が同じ候補が2件できるだけで、
送信時の重複チェックに引っかかる。

アイコンは `ICON` 辞書に `copy` を足す。このアプリのアイコンはすべて自前のインラインSVGで、
線の太さと角の丸みがそろっている。Material Symbols のフォントを読み込むと通信が1つ増え、
既存のアイコンと並べたときに浮くため、同じ形を同じ線画スタイルで描く。

### 4. 時刻のホイール

時刻を押すと、その行の下に時・分の2列ホイールが開く。押した側（開始または終了）だけが開く。

- 時は0〜23、分は0〜59。**分は1分刻み**
- 5分ごとに目盛りを濃くして、回したときの目印にする
- CSS の `scroll-snap-type: y mandatory` で止める。外部ライブラリは使わない
- ホイールにフォーカスを当て、上下の矢印キーでも動かせる

数字を打ち込む入力欄（`normalizeReqTime` / `handleReqTimeInput` / `handleReqTimeBlur`）は
役目を終えるので消す。キーボードだけで操作する人のために、矢印キーでの操作を必ず残すこと。

終了を開始より前に回したときは、長さを保ったまま開始も一緒に前へずらす
（`19:00〜21:00` の終了を `18:00` にすると `16:00〜18:00`）。開始を終了より後ろに回したときも同じく、
長さを保って終了を後ろへずらす。無効な状態を作らせない。

### 5. 「＋ 候補を追加」ボタンの削除

日付を足すのはカレンダー、同じ日を足すのはコピーボタン、と入り口が分かれるため
このボタンをなくす。

あわせて、いま `setReqKind()` が出欠確認に切り替えた時点で候補を1件自動で作っているのを
やめる。カレンダーが空なのに明日の候補が勝手に入っているのは、
「カレンダーで選ぶ」という新しい建て付けと噛み合わない。最初は候補ゼロで始め、
1件も選ばずに送ろうとしたときは既存のチェック（「候補の日時を1件以上追加してください」）で止める。

使われなくなる `addReqOption()` と `shiftReqTimeRange()` は削除する。

## データの持ち方

**`REQFORM.opts` を唯一の正とし、カレンダーの選択状態はそこから毎回導出する。**

```
REQFORM = {
  mode, kind, picked,
  withTime: boolean,      // 「時間を設定する」がONか
  opts: [{date, t1, t2}]  // 候補。dateは 'YYYY-MM-DD'
  // noDate は削除
}
```

カレンダーで光っている日 = `opts` に含まれる日付の集合。別の変数に持たない。

選択状態を二重に持つと、コピーで日付が翌日にずれたときや、行の×で消したときに
片方だけ更新し忘れて食い違う。導出にすれば「カレンダーが光っているのに候補にない」という
状態が構造的に作れなくなる。

新しい日を足すときの初期時刻は、直前の候補（`opts` の末尾）と同じ時刻。
`opts` が空なら `19:00〜21:00`。

## 操作と結果

| 操作 | 結果 |
|---|---|
| カレンダーをなぞる | 範囲内の未選択日を日付順に `opts` へ足す |
| 選択済みの日からなぞる | 範囲内の日を、その日の候補ごとまとめて消す |
| 行の × | その候補1件だけ消す |
| ⧉ コピー | 同じ日付で、前の終了時刻から始まる候補を足す |
| 時刻を押す | その時刻のホイールが開く。もう一度押すか他所を押すと閉じる |
| 月の ◀ ▶ | 表示月を移す。選択状態はそのまま |

候補が1件のときは × を無効にする（今の振る舞いを引き継ぐ）。
同じ日・同じ時刻の候補が二重にできたときは送信時に弾く（`index.html` の既存チェックを維持）。

## 分けかた

計算とHTML組み立てを分ける。`tools/test-fmt.mjs` は `index.html` から関数の本体を切り出して
`new Function` で動かす作りで、文字列に波括弧を含む関数は扱えない。
計算部分を独立した関数にすれば、そのまま検証できる。

検証する関数（HTMLを組み立てない）:

- `reqMins(t)` / `reqHHMM(m)` — `'HH:MM'` と 0〜1439 の数の行き来
- `reqShiftDate(date, days)` — 日付をずらす（月またぎを含む）
- `reqDateRange(a, b)` — なぞった2点から日付の配列を返す（逆向きでも昇順）
- `copyReqOption(opt)` — コピー先の `{date, t1, t2}` を返す。翌日への繰り上げを含む
- `reqApplyTimeChange(opt, field, value)` — 逆転を直した `{t1, t2}` を返す
- `reqCalendarCells(year, month, dates, today)` — カレンダーのマスと選択状態・過去日を返す

ホイールのスクロール位置から時刻を読む部分は DOM を触るので、この検証には含めない。
代わりに、位置と時刻の対応を決める行の高さ（`REQ_WHEEL_ROW`）を CSS と合わせることを
実装時の確認項目にする。

HTMLを組み立てる側（`reqOptionsHTML`、カレンダーの描画）は従来どおり目視で確かめる。

## 触るファイル

| ファイル | 変更 |
|---|---|
| `index.html` | `reqOptionsHTML` の書き換え、カレンダーとホイールの追加、`ICON.copy` の追加、`noDate` と時刻入力欄まわりの削除 |
| `style.css` | カレンダー・ホイール・コピーボタンの見た目 |
| `tools/test-fmt.mjs` | 上記の計算関数の検証を追加 |
| `server/server.js` | 変更なし |

サーバーを変えない理由: `validAttendTime` は `^(?:[01]\d|2[0-3]):[0-5]\d$` で、
すでに1分単位を受け付ける。いま30分刻みに見えるのは画面側の都合だけ。

## 確かめかた

1. `node tools/test-fmt.mjs` と `node tools/e2e.mjs` を通す
2. ブラウザで実際に触る。テストが通っていても見た目は壊れうる
   （`style.css` に書いたルールが `apply.html` の `<style>` に負けて、
   選んだ時間が日付の下に回り込んでいた例がある）
3. 見るもの: なぞって選べるか、選択解除できるか、コピーが正しい時刻になるか、
   ホイールが1分単位で止まるか、矢印キーで動くか、ダークモードで色が沈まないか、
   スマホ幅で崩れないか

## やらないこと

- 出欠を答える側の画面の変更
- `apply.html` との実装の共通化
- 月をまたぐドラッグ（月をまたぐときは ◀ ▶ で移してから選び直す）
- 候補の並べ替え（日付順に自動で並ぶ）
