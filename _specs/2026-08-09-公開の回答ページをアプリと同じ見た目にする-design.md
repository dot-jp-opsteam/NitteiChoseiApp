# 公開の回答ページをアプリと同じ見た目にする

出欠確認まわりの2つを直す。

1. 出欠確認を送ったあと、公開の回答ページへ**ページ遷移していた**のをやめ、
   その場で集計シートを開く
2. 公開の回答ページ（`attendance.html`）を、アプリの「受けた依頼」で開く画面と
   **同じ見た目**にする

## なぜ変えるか

**遷移。** 「誰でも回答OK」で送ると `location.assign()` でアプリを離れ、公開ページへ飛んでいた
（`index.html` の `submitRequest`）。送った本人が見たいのは共有URLと集計であって、
自分で回答するための画面ではない。アプリの外へ出るので、戻るには履歴を戻るしかない。

**見た目。** `attendance.html` は `/style.css` を読まず、ファイルの中に自前のCSSを持っている。
角丸も色も余白もアプリと違い、同じアプリの一部に見えない。
`ae7c81f` で並びだけはアプリへ寄せたが、部品が別物なので寄せきれていない。

## 変えるもの

### 1. 送信後は集計シートを開く（`index.html`）

`submitRequest` の `location.assign(attendShareUrl(request))` を消し、
公開・非公開のどちらでも同じ終わり方にする。

```
REQFORM=null; REQTAB='sent';
closeSheet(); updateBell(); render();
toast(`${request.recipient_ids.length}名に送りました`);
openAttendDetail(request.id);
```

共有URLが発行できなかったときのエラー表示（`public_url` が無い場合）は残す。
URLが無いまま集計を開くと、送った本人が配る先を失う。

### 2. 公開ページを作り直す（`attendance.html`）

`/style.css` を読み込み、アプリと同じ部品で組み直す。ファイル内の自前CSSは消す。

**器。** `.scrim.open` の中に `.sheet` を置き、開いた状態で固定する。
掴みバー（`.grab`）と背景を押して閉じる動きは入れない。閉じても戻る先がない。

**配色。** `localStorage` の `ops_theme_v1` を CSS より先に読んで `data-theme` を立てる
（`index.html` の先頭にあるものと同じ）。同じブラウザでアプリを使っている人は
その設定で見え、初めて開いた人はアプリの既定であるダークになる。

**中身。** `openAttendDetail`（`index.html`）と同じ順・同じクラスで並べる。

| 部分 | クラス | 備考 |
|---|---|---|
| 件名 | `h3` + `.tag` | 「出欠」の札 |
| 送信者 | `.page-sub` | 「◯◯さん ・ 誰でも回答OK」 |
| 締切 | `.due-date.due-detail` | 過ぎていれば `.due-overdue` |
| 共有URL | `.fl` + `.urlrow` | 残す。回答した人が他の人へ回せる |
| 本文 | `white-space:pre-wrap` の div | |
| 確定 | `.hint` | 確定済みのときだけ |
| 集計 | `.fl` + `.atsum` + `.atlist` > `.atl` | |
| 回答 | `.fl` + 名前の `input` + `.attans` > `.attrow` > `.attb` | |

「この日で確定」ボタンは出さない。確定できるのは依頼を出した本人だけで、
公開ページには本人かどうかを見分ける手段がない。

**行を押したとき。** アプリと同じく、シートの中身ごと「◯月◯日 の回答状況」へ入れ替える。
`.atback`（「出欠集計へ戻る」）で戻る。今のアコーディオン展開はやめる。
名前は `.atp` + `.av` の札で出す。公開の回答者に写真はないので頭文字だけになる。
「まだ回答していない人」の区分は出さない（誰が対象かを公開ページは知らない）。

**名前の入力欄。** 「あなたの回答」の見出しの直前に置く。ログインしないので、
名前がないと誰の回答か分からない。今と同じく `localStorage` に控えて、
同じブラウザからは書き換えられる。

**アイコン。** `ic()` と `ICON` は `index.html` の中にある。公開ページで使うのは
`back` と `check` の2つだけなので、その2つのパスをこのファイルへ写す。

### 3. コードは共通化しない

`index.html` と `attendance.html` で描画のコードは重複する。承知のうえで分けておく。

- データの形が違う。アプリは `responses[{user_id,option_id,response}]` と利用者一覧、
  公開APIは `respondents[{id,name,answers[]}]`
- アプリ側の描画は `ME` / `findUser` / `allRequests` などアプリ全体の状態に依存している
- 公開ページはログイン処理を一切通らない別ファイル、という今の作りを崩したくない

見た目のズレは `/style.css` を共有することで防ぐ。マークアップのズレは
`tools/e2e.mjs` の文字列検査で見張る。

## 触るファイル

| ファイル | 変更 |
|---|---|
| `index.html` | `submitRequest` の遷移をやめ、`openAttendDetail` を開く |
| `attendance.html` | 全面的に書き直し（自前CSSを消し、`/style.css` とアプリのクラスへ） |
| `style.css` | 公開ページ専用の微調整のみ（必要なら `pa-` 接頭辞で足す） |
| `tools/e2e.mjs` | 遷移をやめたこと・公開ページが `/style.css` を読むことの検査を足す |
| `server/` | 変更なし |

`server.js` の `PUBLIC_FILES` には `/style.css` が既にあるので、
ログインしていない人にも配信される。サーバーは触らない。

## 確かめかた

1. `node tools/test-fmt.mjs` と `node tools/e2e.mjs` を通す
2. ブラウザで実際に触る
3. 見るもの:
   - 「誰でも回答OK」で送って、ページが変わらずシートが開くか
   - 支部あてで送ったときも同じシートが開くか
   - 公開URLを別ウィンドウで開き、アプリの画面と見分けがつかないか
   - 日程を押すと回答状況へ入れ替わり、戻れるか
   - 名前を入れて回答が送れるか、送り直せるか
   - ダーク・ライトの両方、375px幅で崩れないか
   - 確定済みの依頼を開くと回答欄が消えているか

## やらないこと

- 出欠のデータの持ち方・APIの変更
- 依頼フォーム（候補の選び方）の変更
- `apply.html`（面談申請）の見た目
- アプリと公開ページのコード共通化
