# 出欠は回答した瞬間に完了済みへ／メール履歴とNotion Calendarの説明を外す

3つを直す。

1. 出欠に回答したとき、その依頼を**その場で**「受けた依頼」から「完了済みの依頼」へ移す
2. メール履歴を見る画面と、左メニューの入口をアプリから外す
3. カレンダー連携の説明から、Notion Calendar と iPhone 標準カレンダー（iCloud）のくだりを消す

## 1. 出欠の振り分け

### なにが起きていたか

出欠の依頼に回答しても、**ページを再読み込みするまで「受けた依頼」に残っていた**。

原因は2つある。

**画面が描き直されない。** 出欠の○△×は、依頼を開いたときに出る予定カードから答える。
`vote()` はそのカード1枚だけを差し替えていたので、背後の依頼一覧は古いままだった。

**振り分けの条件が「確定したか」だった。** `requestNeedsAction()` は
「日程が確定していれば完了済み」という判定で、**自分が答えたかどうかを見ていなかった**。

後者は、出欠の依頼に2通りあることから来ている。

| 種類 | 答えるタイミング | 予定の `votable` |
|---|---|---|
| 日程を決める | 候補の段階（`r.responses`）。確定したらもう答えられない | `false` |
| 参加を確認する | 確定した予定そのものに答える（`DB.event_responses`） | `true` |

「参加を確認する」は送った時点で確定する（`keep_votable:true`）作りなので、
「確定したら完了済み」という判定だと、**未回答のまま最初から完了済みへ入っていた**。

### どう直すか

振り分けを「**自分がまだ答えられるか・答えたか**」に変える。

```
function attendStillAnswerable(r){
  if(!r.confirmed)return true;
  if(!r.event_id)return false;          // 日程未定で確定したものは予定が無く、答えようがない
  const ev=(DB.events||[]).find(e=>e.id===r.event_id);
  return !!ev&&ev.votable===true;
}
function requestNeedsAction(r){
  if(!isAttend(r))return !hasConfirmed(r,ME.id);
  if(!attendStillAnswerable(r))return false;
  return !attendResponses(r).some(a=>a.user_id===ME.id);
}
```

`ev.votable!==false` ではなく `ev.votable===true` にしてある。
`votable` の印が付く前に作られた予定は、すべて「日程を決める」で確定したもの。
印が無いものまで「答えられる」扱いにすると、**昔の確定済みが一斉に受けた依頼へ戻ってきてしまう**。

回答したあとは `renderQuiet()` で一覧まで描き直す。`renderQuiet()` は登場アニメを
通さないので、ダークテーマでも暗転しない。シートの中のカードから答えたときだけ、
シート自体は作り直されないので、そのカード1枚を差し替える。

受けた依頼に並ぶ出欠のタグは、「確定」より先に「**未回答**」を出す。
日にちが決まっている参加確認でも、ここでやることは「答える」ことだと分かるようにするため。

## 2. メール履歴の撤去

`openMailHistory()` / `openMailDetail()` と、左メニューの入口
（スタッフ「メール履歴」／インターン生「受信メール」）を消す。

**消すのは見る場所だけ。** 面談の確定・不成立のメールはこれまでどおり送られ、
サーバー側の記録（`emails` テーブル、`POST /api/mail/send` が書き込む）も残り続ける。
必要になれば画面を戻せる。

## 3. カレンダー連携の説明

`openGoogleCalendarSettings()` の2か所から消す。

- 連携済みのとき：「Notion Calendarをお使いの場合も…iPhone標準カレンダー（iCloud）は別対応が必要です。」
- 未連携のとき：「Notion CalendarでGoogleアカウントを表示している場合も対象です。」

iPhone 標準カレンダーへの購読URL方式（`2026-08-08-依頼まわりの改善-requirements.md` の項目4）は
別の機能として残る。ここで消したのは説明文だけ。

## 確かめたこと

`tools/e2e.mjs` に2件の検査を追加・更新した。

- 未処理件数は、未完了の通常依頼と、**まだ答えられる**未回答の出欠確認を数える
- 出欠の回答後は一覧も静かに描き直す（`renderQuiet()`）

`test/test-mock.js` の `ev_att3`（「日程を決める」で確定した予定）に `votable:false` を明記し、
本番と同じ形にした。

ブラウザでも確かめた。

| 経路 | 結果 |
|---|---|
| 参加を確認する・未回答 | 受けた依頼に「未回答」で出る |
| → ○を押した直後 | 受けた依頼から消え、完了済みに出る（再読み込み不要） |
| 日程を決める・回答送信 | 同じくその場で完了済みへ |
| 確定済みの日程調整（未回答） | 完了済みのまま（変化なし） |
| ホームのカードから回答 | `viewquiet` が付き、暗転しない |
| 左メニュー（スタッフ／インターン生） | メール関係の項目が消えている |
| カレンダー連携 | Notion・iCloud の文字が出ない |

`test-fmt.mjs` 70件・`e2e.mjs` 489件すべて成功。
