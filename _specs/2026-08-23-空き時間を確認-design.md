# 空き時間を確認（日程調整URL）— 設計

2026-08-23

## 何をするものか

スタッフが「空き時間を確認」を押すと、**そのスタッフ専用の公開URL**が1本できる。
学生（アカウント不要）はそのURLを開き、**自分の空いている時間**をカレンダーで選んで送る。
スタッフは依頼画面で、**複数の学生の空き時間がどこで重なっているか**を見る。

面談申請（`apply.html`）との違い：

| | 面談を申請 | 日程調整（新） |
|---|---|---|
| 担当スタッフ | 学生が画面で選ぶ | URLに含まれる（選べない） |
| 希望順 | 「選んだ希望日時」で並べ替える | **なし**（空いている時間を知るだけ） |
| 送信後 | 面談（`interviews`）ができる | 回答が溜まるだけ。面談にはならない |
| URL | 支部に1本 | **依頼1件に1本** |

## 画面

### 1. 発行（スタッフ・依頼画面）

依頼画面のボタンを3つにする：`日程を決める` / **`空き時間を確認`** / `タスクを追加`。

押すと件名だけのフォームが出る（例：「山田さんとの日程調整」）。
発行すると `https://<本番>/f/<合言葉>` が出て、その場でコピーできる。
1本のURLに何人でも回答できる。締め切り・削除の機能は持たない。

### 2. 学生側（新ファイル `free.html`、ログイン不要）

`apply.html` を土台にした別ファイル。ログイン処理を一切通さないため、
既存の作り（`apply.html` / `attendance.html` と同じ方針）に合わせる。

- 見出しは **「日程調整」**
- 欄：**お名前**（必須）／**週カレンダー**（空いている時間・必須）／**その他**（任意）
- 出さないもの：担当スタッフの選択欄、「選んだ希望日時」の並べ替えブロック
- 枠：そのスタッフの受付時間 − 確定済み面談（面談申請と同じ生成）
- 見られる範囲：**今日から3週間**（面談申請と同じ）
- 流れ：入力 → 確認 → 送信 → 控え（面談申請と同じ3段）

同じ件名の中で**名前が同じ回答は上書き**する。書き直しができる。

### 3. スタッフ側の一覧（依頼画面）

タブを3つにする：`受けた依頼` / `完了済みの依頼` / **`空き時間`**。
一覧には件名・発行日・回答人数を並べる。

1件を開くと：

- **週の表**：人数が多い枠ほど濃く塗る。枠を押すと、その時間に空いている人の名前が出る
- **下に上位リスト**：「8/25（月）14:00〜15:00・3人（山田・佐藤・鈴木）」を数件

面談の確定はしない（見るだけ）。

### 4. 知らせ

回答が届いたら、発行したスタッフ本人にお知らせ＋端末通知（面談申請と同じ扱い）。

## データ

新しいテーブルを2つ足す。

```
freeslot_requests
  id          TEXT PRIMARY KEY      -- fs_xxxxxxxxxxxx
  token       TEXT UNIQUE           -- URLの合言葉
  staff_id    TEXT                  -- 発行したスタッフ（＝担当）
  branch_id   TEXT
  title       TEXT                  -- 件名
  created_at  TEXT

freeslot_responses
  id          TEXT PRIMARY KEY
  request_id  TEXT
  name        TEXT                  -- 学生の本名
  choices     TEXT                  -- 選んだ枠のISO文字列（JSON配列）
  all_day     TEXT                  -- 「終日OK」の日（JSON配列）
  note        TEXT
  created_at  TEXT
  UNIQUE(request_id, name)          -- 同じ名前なら上書き
```

## API

公開（ログイン不要・回数制限を付ける）：

| メソッド | パス | 中身 |
|---|---|---|
| GET | `/api/free/:token` | 件名・スタッフ名・支部名（`limitPublicRead`） |
| GET | `/api/free/:token/slots?week=` | 週の枠（`limitPublicRead`） |
| POST | `/api/free/:token` | 回答を送る（`limitPublicWrite`） |

スタッフ用（`requireAuth`）：

| メソッド | パス | 中身 |
|---|---|---|
| POST | `/api/freeslots` | 発行（件名を受け取り、tokenを返す） |
| GET | `/api/freeslots` | 自分が発行した一覧（件名・発行日・回答人数） |
| GET | `/api/freeslots/:id` | 1件の回答すべて（名前と枠） |

`POST /api/free/:token` は面談申請と同じく、送られた枠を
`slots.selectableTimes()` で照らし合わせ、受付時間外や埋まった枠は弾く。

## 配信

- `/f/<token>` → `free.html`（`/i/` `/a/` と同じ形。合言葉の正しさはAPIで確かめる）
- `PUBLIC_FILES` に `/free.html` を足す

## テスト

- `tools/e2e.mjs` に「空き時間」の区画を足す
  - 発行 → 公開APIで読める → 回答できる → 一覧に人数が出る
  - 他支部のtokenや存在しないtokenは弾かれる
  - 同じ名前で2回送ると1件になる（上書き）
  - 受付時間外の枠を送ると409
- `tools/test-ratelimit.mjs` に `/api/free/:token` の回数制限を足す
- `tools/test-fmt.mjs` にかぶり集計（人数の数え上げ・上位の並べ替え）の検査を足す

## 気をつけること

- CSSのクラス名には接頭辞を付ける（`fs-` にする）
- `free.html` を作ったら `PUBLIC_FILES` に足す（無いと404）
- 学生のメールアドレスは受け取らない（本名だけ）。`scrubEmail` の対象を増やさない
- 料金の発生する仕組みは使わない（テーブル2つ・既存のTursoのみ）
