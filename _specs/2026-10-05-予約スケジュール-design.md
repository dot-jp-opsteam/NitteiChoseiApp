# 予約スケジュール（Googleカレンダーの予約スケジュールの再現）— 設計

2026-10-05（チャットで①〜④を承認済み。本番公開まで実装してよいと指示あり）

## 決まったこと（ユーザーの回答どおり）

- 予約するのは**インターン生（公開ページ）**。空き枠を1つ選ぶと、その場で確定する
- いまの面談申請（希望を複数出す→スタッフが確定）は**両方残す**
- Googleの予定は**空きだけ見せる（Googleと同じ）**。中身は出さず、予定のある時間を枠から消す
- 予約ページは**スタッフごとに複数（Googleと同じ）**。1本ごとに公開URL
- 連絡は**Googleの招待メールで届ける**。メールアドレス必須
- 入れる機能：予約期間・特定日の調整／前後の余白・1日の上限／フォームの質問・場所・Meet／予約者による変更・キャンセル
- **日本時間固定**（タイムゾーン切替なし）
- **予約前のメールアドレス確認を入れる**（アプリのメール送信が設定済みのときだけ使える）
- 除外：支払い（有料）、タイムゾーン切替、グループ予約

## 前提（私が置いたもの）

- 予約スケジュールを作れるのはGoogleカレンダー連携済みのスタッフだけ（予約で予定を作るため）
- リマインダーは keepalive（5分おき）でサーバーが起きている前提で、サーバー内の定期処理で送る

## 構成（案A）

| 置き場所 | 役割 |
|---|---|
| `server/booking.js` | 枠の計算（純粋関数）と設定の正規化 |
| `server/google.js` | freeBusy・Meet付き作成・`sendUpdates` の追加。API の宛先を環境変数で差し替え可能に（試験用） |
| `server/server.js` | テーブル `booking_pages`、スタッフ用API、公開API、リマインダー、webhookでの取消検知 |
| `book.html` | 公開の予約ページ `/b/<合言葉>` と変更・キャンセル `/b/manage/<合言葉>` |
| `index.html` | ナビ「予約スケジュール」：一覧・編集シート。面談詳細に予約の情報とキャンセル |

### データ

`booking_pages (id, staff_id, token UNIQUE, active, data JSON, created_at, updated_at)`

`data`：`title, color, duration, repeat('weekly'|'none'), weekly{0..6:[{s,e}]}, overrides{YYYY-MM-DD:[{s,e}]}（空配列=休み）,
maxDays, minNoticeHours, startDate, endDate, bufferMin, maxPerDay(0=無制限), calendars[], location{type:'meet'|'place'|'phone'|'none', text},
description, phone('off'|'optional'|'required'), questions[{id,label,required}], verifyEmail, reminders[分]`

予約は `interviews` に `status:'fixed'` で入れる。`data` に
`source:'booking', booking_page_id, booking_title, duration_min, guest_email, guest_phone, answers, manage_token, googleEventId, meet_url, reminders_sent[]`。
キャンセルは `status:'failed'` ＋ `cancelled:true, cancelled_by('guest'|'staff'|'google')`。

## 枠の計算

1. 曜日ごとの区間（または「繰り返さない」なら特定日の区間だけ）を、開始から枠の長さで切る。はみ出す枠は作らない
2. 特定日の上書き（空配列＝休み）
3. 締め切り（既定4時間前）・何日先まで（既定60日）・開始日／終了日
4. 次と重なる枠を消す：選んだGoogleカレンダーの busy（freeBusy）／スタッフの確定済み面談すべて／このスケジュールの予約の前後の余白
5. 1日の上限（このスケジュールの予約数）

freeBusy はページ表示時は60秒キャッシュ、予約送信時は取り直し＋ロック。Googleに問い合わせられなければ枠を出さない。
予約時はGoogleに予定を作り（ゲスト＝予約者、`sendUpdates=all`、Meet任意）、失敗したら予約しない。
既存の申請ページの空き枠計算では、予約の長さぶんを埋まりとして扱う。

## 公開API（回数制限あり）

`GET /api/book/:token` / `GET /api/book/:token/slots?week=` / `POST /api/book/:token/verify` / `POST /api/book/:token`
`GET|PATCH|DELETE /api/book/manage/:token`（変更・キャンセルは開始時刻まで）

## スタッフ用API

`GET|POST /api/booking-pages`、`PUT|DELETE /api/booking-pages/:id`、`GET /api/booking-pages/calendars`、
`POST /api/interviews/:id/cancel-booking`。面談の PATCH は予約由来のものを受け付けない（キャンセルは専用API）。

## 知らせ

予約・変更・キャンセル：Googleの招待／更新／取消メール（予定の説明欄に変更用リンク）＋アプリ内通知＋プッシュ。
リマインダー：設定したタイミング（既定 前日・1時間前）にアプリのメールで送る（メール未設定なら設定欄を出さない）。
Googleで予定が消されたら webhook で検知してキャンセル扱い。
